# AI 小说工坊

一个本地运行的 AI 小说创作桌面级 Web 应用。接入你自己的大模型 API，把「一个想法」变成一部完整的小说。

## 功能特性

- **一键创作**：输入灵感想法，选择小说类型，AI 自动生成书名、世界观、剧情大纲、角色关系网与完整章节规划
- **逐章创作**：按章生成内容，支持设定每章字数（500-8000 字），生成过程中实时流式显示
- **无 AI 味**：内置「人类写作风格铁律」—— 禁用套话总结腔、机械排比、辞藻堆砌、空洞升华、功能化对话等 AI 高频痕迹；生成后支持一键「去 AI 味」润色，也可在设置中开启「自动去除 AI 味」，每章完成后自动按人类文风重写
- **铁律模式（生成质量门）**：默认开启的硬性质量保障 —— 生成与「去 AI 味」都走强制闭环：润色 → AI 味检测 → 未达标自动再润色（最多 3 轮，每轮带上一次检测出的具体问题清单与 AI 高频词），并叠加程序级「AI 高频词黑名单」硬过滤，检测通过、不再命中黑名单词才算完成并写入正式章节，从机制上杜绝 AI 味残留；可在「模型设置」中关闭
- **长篇小说支持**：专为长篇设计的分层记忆机制 —— 每章自动生成剧情摘要，创作时参考「前情摘要 + 最近章节全文」，可稳定支撑数十万乃至千万字的长篇连载，且不受上下文窗口限制
- **创作对话**：内置 AI 对话面板，创作间隙随时与 AI 讨论剧情走向、人物设定、修改意见，AI 记得你的设定与进度
- **人物关系网**：AI 自动提取角色与关系，可视化关系图谱（力导向图），支持手动增删改
- **角色卡片**：为每个角色建立性格、背景、简介卡片，支持从章节内容智能分析提取
- **写作风格提取**：导入其他作者的小说文本，AI 自动提取其写作风格（叙述视角、句式、用词、对话、描写、开篇收尾等）并保存到风格库；支持千万字级超大文本，会自动从开头、中间、结尾抽样分析；创作时可单独选用或融合多种风格，生成与润色都会参考所选风格
- **逐章确认创作**：一次只生成一章，完成后弹出询问是否修改（可选「去 AI 味润色」或「手动修改」），确认满意后由你点击「生成下一章」继续；生成过程中内容实时写入浏览器草稿，中途刷新或关闭页面后可一键恢复续写，不丢正文
- **AI 味检测**：对任何已写章节一键检测 AI 痕迹，输出 0-100 分评分，并按「总结腔/空洞升华/机械排比/辞藻堆砌/功能化对话/套路描写/过度工整/高频口水词」分维度逐条指出问题原文、诊断与修改建议；评分超过 30 分可直接一键润色。工具栏「AI 味走势」可查看全书每章检测评分曲线
- **真人文风参照**：粘贴一段真人作家的文字作为本作文风参照，生成与润色会模仿其句子长短、语气、节奏与叙述口吻，进一步消除 AI 腔
- **文风基准**：从已写章节提炼本作的固定文风基准并长期保存，之后即使切换到大模型（DeepSeek / GPT / Claude…），生成与润色的写法语感也保持一致
- **伏笔记忆**：每章生成后 AI 自动分析本章新埋下 / 已回收的伏笔并记录，后续生成章节时自动注入「待回收伏笔」清单，防止前期埋的坑后期被遗忘；支持手动新增、回收、智能分析
- **世界观设定集**：按人物 / 地点 / 势力 / 物品 / 时间线等分类维护恒定设定，生成章节时自动注入并要求不得与既定设定冲突，保证长篇写作前后一致
- **章节历史版本**：每次「重新生成」「去 AI 味」「恢复版本」覆盖章节前自动备份旧内容（每章保留最近 20 个版本），随时可查看并一键恢复，不再怕误覆盖丢稿
- **压缩上下文**：长篇连载时点击「压缩上下文」，把已写内容压缩成一份故事状态简报，后续生成用它替代「前情摘要 + 最近章节全文」，大幅节省 tokens；可随时「恢复上下文」回到完整记忆模式，顶栏实时显示当前上下文估算大小
- **本地记忆**：小说、章节、对话、角色全部持久化在本地 SQLite 数据库，关闭软件后重新打开即可续写
- **小说即文件夹**：每一本小说在本地「作品存放目录」下拥有一个以小说名命名的独立文件夹，每一章保存为一个独立的 TXT 文本文件（`第3章-章节标题.txt`），内容随生成 / 润色 / 编辑自动同步，可直接用记事本或任意阅读软件打开；作品存放目录可在「设置 → 作品存放位置」自由指定（可安装到任意盘 / 分区），切换目录时可一键迁移已有作品
- **一键复制 / 导出**：单章一键复制、全书一键复制、导出 Markdown 文件
- **编辑自动保存**：手动编辑章节时内容自动存入本地草稿，误关页面或刷新后重进编辑器可一键恢复，不再丢字
- **深色模式**：侧边栏一键切换浅色 / 深色主题，偏好自动记忆
- **可接入任意模型**：OpenAI、DeepSeek、Kimi、通义千问、智谱、Ollama（本地离线）及任意 OpenAI 兼容端点

## 打包为桌面软件（Electron）

### 打包前准备

```bash
# 1. 先构建前端产物（必须，产物会被打进安装包）
cd web && npm install && npm run build

# 2. 安装打包依赖（含 Electron 运行时，下载较大）
cd ../desktop && npm install
```

### 生成安装包

```bash
cd desktop
npm run prep:win      # Windows：NSIS 安装包（x64）
npm run prep:mac      # macOS：dmg（arm64 + x64）
npm run prep:linux    # Linux：AppImage
```

`prep:*` 命令会先运行 `node scripts/prepare-deps.cjs`：把后端依赖（`server/node_modules`）复制到 `.build/server-deps` 暂存目录再打包。这样能绕开 electron-builder 对 `node_modules` 目录的智能过滤，确保后端依赖 100% 打进安装包——**不要使用 `dist:*` 直接打包**，否则产物缺依赖，安装后内置服务启动即退出（白屏 / 「内置服务进程异常退出」）。

产物输出到 `desktop/release/`：

- Windows：`AI小说工坊 Setup x.x.x.exe`
- macOS：`AI小说工坊-x.x.x-arm64.dmg` / `-x64.dmg`
- Linux：`AI小说工坊-x.x.x.AppImage`

首次运行时如出现 Windows SmartScreen 提示（未签名），选择「更多信息 → 仍要运行」即可。

### 打包内容说明

安装包内会包含三部分（`extraResources`）：

- `server/`：后端代码 + 运行时依赖（express/cors），**不包含** `server/src/data/`（本地开发数据库与作品不会混入安装包）
- `server/node_modules/`：后端依赖（由 `prepare-deps.cjs` 预复制，确保不丢失）
- `web/dist/`：前端构建产物
- 应用启动后自动在 3001~3010 之间挑选空闲端口 fork 启动内置后端，主窗口直接加载本机后端地址

### 桌面版数据存放位置

- 数据库与设置：`%APPDATA%/AI小说工坊/`（macOS：`~/Library/Application Support/AI小说工坊/`，Linux：`~/.config/AI小说工坊/`），独立于安装目录，升级/卸载不丢数据
- 作品文件（小说文件夹 + 每章 TXT）默认在「文档/AI小说工坊/作品」，可在应用内「设置 → 作品存放位置」改到任意盘

### 应用图标

默认使用 Electron 图标。正式发布时在 `desktop/package.json` 的 `build` 段补充 `icon` 字段：

```json
"win": { "icon": "build/icon.ico", "target": [{ "target": "nsis", "arch": ["x64"] }] },
"mac": { "icon": "build/icon.icns", "category": "public.app-category.productivity", "target": [{ "target": "dmg", "arch": ["arm64", "x64"] }] },
"linux": { "icon": "build/icon.png" }
```

生成规范图标（至少 512×512 PNG）后，electron-builder 会自动转换各平台所需格式。

### 开发模式运行桌面版

```bash
cd desktop
# 加载前端 dev server（需先启动 web 的 npm run dev）
npm run dev
# 或使用已构建的前端 + 内置后端直接启动：
npm start
```

### 常见打包问题

**Linux 下 AppImage 无图标/窗口不关联桌面**：在 package.json 顶层添加 `"desktopName": "ai-novel-studio"`，并在 `build.linux` 段添加 `"syncDesktopName": true`。

**打包后启动黑屏**：确认已先执行 `npm run build` 生成 `web/dist/`，并检查 `server/src/data/` 是否被排除（不应随包发布本地开发数据）。

**端口冲突**：内置后端自动在 3001~3010 范围内挑选空闲端口，通常无需处理；若占用全部端口，可设置环境变量 `PORT` 指定起始端口。

## 快速开始

### 桌面版（推荐）

本软件同时提供 Electron 桌面版，不依赖浏览器，安装后可像普通软件一样选择安装到任意盘。打包、数据位置与常见问题详见上文「打包为桌面软件（Electron）」章节。

Windows 一键生成安装包（推荐直接双击项目根目录 `build-installer.bat`）：

```bash
cd desktop
npm install
npm run prep:win
```

### Web 开发模式（浏览器访问）

```bash
./start.sh
```

或分别启动：

```bash
# 终端 1：后端（端口 3001）
cd server && npm install && npm start

# 终端 2：前端（端口 5173）
cd web && npm install && npm run dev
```

浏览器访问 http://localhost:5173

### 配置模型

1. 打开页面左侧「模型设置」
2. 选择服务商（如 DeepSeek、Kimi），或选择「自定义」填写任意 OpenAI 兼容端点
3. 填入你的 API Key 与模型名称
4. 点击「测试连接」，成功后保存

### 开始创作

1. 「新建小说」→ 填写标题、类型、灵感想法、每章字数、目标章节数
2. 进入创作工作台 → 左侧输入/确认灵感 → 点击「AI 生成创作方案」
3. 方案生成后（含角色与章节规划），点击「生成下一章」逐章创作
4. 创作间隙在右侧「创作对话」与 AI 讨论剧情
5. 完成或需要时：一键复制单章/全书，或导出 Markdown

## 技术架构

- **前端**：Vue 3 + Vite + Element Plus + ECharts（关系图）
- **后端**：Node.js + Express + 内置 `node:sqlite`（无需原生编译）
- **数据存储**：SQLite（`server/data/novel-studio.db`），全部本地保存
- **LLM 接入**：OpenAI 兼容 Chat Completions 协议，支持流式 SSE

```
novel-studio/
├── server/            # 后端 API（桌面版内置，Web 版独立运行）
│   ├── index.js       # Express 入口（含前端静态托管）
│   └── src/
│       ├── db.js      # SQLite 数据模型
│       ├── llm.js     # 大模型客户端（流式/非流式）
│       ├── prompts.js # 提示词组装（设定/大纲/章节/摘要/对话）
│       ├── lib.js     # 业务辅助（字数统计/记忆组装/伏笔/设定/备份）
│       ├── storage.js # 作品文件夹 + 每章 TXT 持久化
│       └── routes.js  # 业务 API
├── web/               # 前端
│   └── src/
│       ├── views/     # 书架/工作台/设置/风格库
│       ├── components/  # 章节/对话/角色/关系/伏笔/设定面板
│       ├── stores/    # Pinia 状态（编辑器/设置）
│       └── api/       # HTTP + SSE 流式封装
└── desktop/           # Electron 桌面版
    ├── electron/main.cjs  # 主进程（内置后端 + 窗口）
    └── package.json       # electron-builder 打包配置
```

## 数据与隐私

- 所有作品数据仅保存在本机 SQLite 文件中，不经过任何第三方服务器
- API Key 仅保存在本机，仅用于调用你配置的模型服务
- 模型调用由后端转发到你配置的 Base URL，前端不直接接触 Key

## 常见问题

**生成报错「认证失败」**：检查 API Key 是否正确、服务商是否填写了正确的 Base URL。

**生成的字数达不到设定**：可适当调大「单次最大输出 Token」（设置页），或把每章字数控制在模型单次输出能力内（部分模型单次约 4k-8k token，中文约对应 3000-6000 字）。

**长篇小说能写多长**：理论上不限。每章独立持久化，AI 通过摘要链保持剧情连贯，字数只受磁盘空间限制。

**想换模型**：在「模型设置」切换服务商即可，已有作品数据不受影响。
